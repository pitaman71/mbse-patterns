# Test plan

One suite per notebook, with the same case IDs, in the same order, in both implementations; each case is a markdown
cell `## ID · title` followed by one code cell. `support.py` holds the shared helpers and the address book the suites
use: a singleton directory lists contacts, and contacts own phones, each phone with one entry. TypeScript's plan lists
only its differences.

| Notebook | Suite | Covers |
|---|---|---|
| `01_Predicates.ipynb` | CON | A predicate built fluently (name, description, symbols and parameters added in order, conditions from a lambda or a writer, which `requires` and `forbids` add up, the builder's declared variables; clone, update, resolve, and the builder's refusals); static problems (no rule, a symbol's schema not a named reference object schema, non-core operations, unbound names) and `check` (labelled by name, a predicate of a set without a name, a name defined twice, a set of non-predicates); a set's order and builder; predicates as data (symbols written by schema name with any store, a shared rule written once, read back through `OfStore(store)` to the store's schemas, refused through `Builders` for named schemas, an inline schema and an untyped parameter round trip, mbse-schemas' validation, `update` through the store); decoding refused (a rule at another index, an unset link) and a set of non-predicates read then refused, a blank predicate; `register` in a proxy store; a predicate applied by reference (its arguments bound to its symbols and parameters, `call`, the wrong number of arguments, a non-predicate, evaluation, written once and read back as one object, a cycle) |
| `02_Validators.ipynb` | VAL | Each match checked (holds, does not hold, unknown); a value of another schema; `Reachable` over the cross product of two symbols' objects, labelled by match; `unknown` as report, ignore or violation, and a bad mode refused; a rule that raises or gives a non-bool, reported in place; predicates that cannot be right, or that have parameters, refused when the validator is made |
| `03_Queries.ipynb` | QRY | Matches stream lazily over the extents (what the singleton reaches, not transient objects); `unknown`; variables bound once, objects as variables, conjuncts of variables alone tested first; the extents read at the first match; queries refused when made (a symbol's schema not a named reference object schema or not in the store, a variable named like a symbol, unbound names, non-core operations) and a non-bool rule, when read; several symbols: the cross product, hops through relations (any number, at most one by `unique`, both ways, a target of another schema filtered out), conjuncts tested early, and `explain`; every shape that is not a hop; `Scan` delegates every store method, `random` included; `select` asks a queryable store and scans others, a store of bound classes included |
| `04_Conformance.ipynb` | CONF | Committed snapshots current; the same cases and byte-identical JSON in every implementation; every implementation's JSON and YAML read back to the same sets |
| `05_Skill.ipynb` | SKL | The packaged skill current; its complete programs run; every link in the agent guides resolves |
| `06_Algebra.ipynb` | ALG | The algebra's terms built by their builders (a schema or its name; several symbols nested; the builder's symbols as variables; a quantifier without a symbol; conditions added from an instance; `Contains` from a lambda or a `def`, and what it refuses; the extent, option and choice builders) and checked (mixed with Basic's, which Basic alone refuses; unbound names, weights summing to 1, positive weights, empty choices, non-options, unnamed schemas, specs that are neither data nor a builder callable); evaluation over the store (mandatory, forbidden and possible links, extents read once per evaluator, Kleene's `choice`, an unknown object, unknown schemas); predicates of the algebra (without symbols: validated and queried once; `Contains` as a hop, at most one by `unique`, `forbids` of an `Exists`, a relation of three links whose condition names its link) and their round trip as data |
| `07_Distributions.ipynb` | DST | A distribution built fluently (symbols, cases in decreasing precedence with float weights, predicates by reference and inline, clone and update, the builder's variables, `OfCase.resolve`); checked (symbols, weights, non-cases, no case, a case's predicate's symbols and parameters, a missing predicate) when asked and when drawn from; a match's weight (the first holding case, unknown not holding, none); `Sample` (proportions over many draws, a match weighing nothing never drawn, the same draws from a seed, another from a split stream, no weight); distributions as data (one predicate written once and read back as one); distributions of values (built, their domains, refused specs, options; draws checked against their properties' types and schemas, a case's arguments, a property that is not a native) and a distribution with draws as data |
| `08_Generators.ipynb` | GEN | Sampling's vectors from PCG32(42, 54) (`uniform`, `below` of one and two words, `weighted`), its ends, rejection, a zero weight, and its refusals; `Generate` (the same names from one seed in both languages, other seeds and split streams, proportions over many steps, `settings` through equalities on either side, conjunctions and applications, and what it ignores); cases refused (what equalities build does not satisfy the case, satisfies an earlier case, or a later one), an unchecked distribution; generated data listed, queried, validated and written; the exact samplers (`between`, `normal`, `poisson` over 500, `geometric`, `log` and `exp` and their edges, the polar method's rejection, a Poisson whose terms underflow, and every refusal); draws (a case conditioned by rejection, `Generation`'s counts, a draw reading what is drawn, ints and floats, an equality not redrawn, a constant, a case no attempt satisfies, a uniform's bounds reversed, a parameter that is not a number) |

## Not testable yet

Patterns, distributions, the pseudorandom generator, generators and characterizers (designed in `docs/PATTERNS.md`,
not built); standing and asynchronous queries; native queries of a database store.
